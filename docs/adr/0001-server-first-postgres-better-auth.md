# Server-first: Postgres, better-auth и Drizzle вместо IndexedDB и офлайна

uWeek был local-first: задачи жили в IndexedDB браузера, приложение работало офлайн через service worker, данные не покидали устройство. Владелец выкладывает сервис публично, а его агенты должны читать и менять задачи через REST API и MCP. Браузерное хранилище этого не позволяет, поэтому источником истины становится сервер: Postgres 18 в отдельном контейнере на VPS владельца, вход по ссылке на почту и через Google с сессиями в той же базе. IndexedDB, service worker и офлайн-сборка удаляются; интерфейс работает только онлайн (спека `.scratch/uweek-cloud/spec.md`).

Самые дорогие для замены библиотеки выбраны тикетом 01: **Drizzle** для доступа к базе и миграций и **better-auth** для аутентификации. Версии и полный список — в `docs/tech-stack.md`.

## Considered Options

- **Prisma вместо Drizzle.** Отклонено: стабильная 7 уже на теге `prev`, а 8 — release candidate вне peer-диапазона better-auth; отдельный DSL и шаг `prisma generate`; 133 пакета против 15.
- **Kysely вместо Drizzle.** Без зависимостей, но миграции и типы базы пишутся вручную.
- **next-auth / Auth.js, lucia, своя реализация.** next-auth 5 существует только как beta, lucia и arctic помечены deprecated, своя реализация magic link и OAuth — лишний риск безопасности.

## Consequences

- Данные пользователей хранятся на сервере, поэтому изоляция по `user_id` — обязанность единого слоя операций, через который ходят интерфейс, REST API и MCP.
- Схема таблиц сессий и аккаунтов задаётся better-auth; при её обновлениях нужны миграции через drizzle-kit.
- Drizzle 1.0 в стадии release candidate: переход на него — ожидаемый мажорный апгрейд, peer-диапазон better-auth его уже допускает.
