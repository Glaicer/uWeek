# Технологический стек по умолчанию

Дата проверки: 2026-10-11. Версии сверены по npm registry (`npm view <пакет> version`), не по памяти. Планировщик пакетов — pnpm 12.3.4, Node.js 24.17.0; в `package.json` версии закреплены точно (без `^`/`~`).

Этот файл — договорённость о «чем мы решаем типовые задачи», чтобы каждая новая функция не заново выбирала инструмент. Спека продукта выше этого списка: `nextjs-migration` запрещает серверное хранение задач, аналитику и telemetry с пользовательскими данными, внешние шрифты и CDN, редизайн и новый формат копии.

## Правила добавления новой зависимости

1. Сначала проверить, не решает ли задачу JavaScript, стандартный Web API, или уже установленная зависимость.
2. Взять текущую стабильную версию из registry (`npm view <пакет> version`), прочитать официальную документацию/Context7 и changelog. Версия из памяти не принимается.
3. Проверить: совместимость с Node 24.17, TypeScript 6.0.3, ESLint 10.12, React 19.3.0; peer-зависимости; лицензию; размер транзитивных зависимостей; влияние на офлайн-оболочку — каждый клиентский рантайм увеличивает набор ресурсов, которые обязан закэшировать `scripts/sw.js`.
4. Оценить по спеке: не тянет ли зависимость сетевые запросы, внешние шрифты/CDN, telemetry, сбор пользовательских данных, не ведет ли к редизайну.
5. Закрепить точную версию в `package.json`, обновить `pnpm-lock.yaml` через `pnpm install` (без `--frozen-lockfile` при добавлении).
6. Ставить в том же коммите, где появляется код, который ее использует. Установка «на будущее» запрещена.
7. Обновить этот файл и, если зависимость меняет архитектуру, добавить ADR в `docs/adr/`.
