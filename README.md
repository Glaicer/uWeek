# YourWeek

Личный недельный планер без регистрации и облачной синхронизации: задачи, списки «Когда-нибудь», заметки, чек-листы, цвета, поиск, CSV-импорт и полная JSON-копия. Данные сохраняются в IndexedDB и доступны офлайн после загрузки оболочки. Интерфейс — декларативный React (Next.js App Router), сервер только доставляет приложение: Node.js runtime с обычной production-сборкой `next build` и запуском `next start`.

## Запуск

Нужны Node.js 24+ и pnpm 12.3.4.

```sh
pnpm install --frozen-lockfile
pnpm dev        # next dev на http://127.0.0.1:4200
```

Production-поставка:

```sh
pnpm build      # next build + подготовка офлайн-оболочки в public/sw.js
pnpm start      # next start на http://127.0.0.1:4201
```

Для production указывайте свой постоянный порт: `pnpm exec next start --hostname 127.0.0.1 --port ПОРТ`. Сохраняйте один и тот же адрес (HTTPS или localhost с постоянным портом) — данные привязаны к origin, и его смена потребует ручного переноса копией. Планер доступен по адресу `/`; подкаталог сайта не поддерживается. Не требуются MongoDB, аккаунты, секреты или внешние сервисы.

Enter или «Добавить» сохраняет задачу, Escape отменяет ввод. Пустой ввод ничего не создаёт.

## Обновление с прежней статической версии

Профиль с прежней версией (статическая сборка, коммит 8657507) продолжает работу без очистки данных сайта: откройте тот же адрес, и новый service worker установится в фоне поверх старого. Статус «Обновление готово…» предлагает сохранить изменения и закрыть вкладки; новая оболочка применяется при следующем открытии, черновики не сбрасываются. База `yourweek` (схема v3), история импортов и настройки не переносятся и не конвертируются — переустановки или повторного CSV-импорта не требуется. Неудачное обновление оставляет прежнюю рабочую оболочку. Перед обновлением рекомендуется скачать JSON-копию в разделе «Данные».

## Офлайн-работа

Офлайн-оболочка создаётся только `pnpm build`, не в режиме dev: `scripts/build-next.mjs` собирает Next.js, требует статически пререндеренный HTML маршрута `/`, складывает его и клиентские ресурсы `.next/static` вместе с `public/` в манифест и записывает готовый worker в `public/sw.js`. Файлы `public/sw.js` и `public/index.html` — артефакты сборки: они не хранятся в git и перезаписываются каждой сборкой. Навигационные запросы офлайн обслуживаются HTML одной сборки, поэтому HTML и чанки всегда согласованы по общей хеш-версии кэша. Worker отдаётся с типом `application/javascript` и обновляемой политикой кэша (не immutable).

Первый запуск требует сети: дождитесь статуса «Готово к работе офлайн» — это подтверждение завершённого кэширования всех ресурсов сборки, включая чанки редактора, поиска, импорта и восстановления, не только посещённых экранов. После этого закройте браузер и откройте тот же адрес в том же профиле без сети и без работающего сервера: просмотр, создание, редактирование, чек-листы, переносы, поиск, импорт CSV с устройства, скачивание и восстановление копий работают. Первый запуск в совершенно новом профиле без сети не гарантируется.

`next dev` никогда не регистрирует worker и не обещает офлайн. Телеметрия Next.js отключена: `NEXT_TELEMETRY_DISABLED=1` выставлен во всех скриптах; при собственном запуске иными способами выставляйте её тоже. Обновление устанавливается в фоне, но не перезагружает открытые вкладки. Неудачное обновление оставляет предыдущую оболочку и задачи; удаляется только устаревший кэш `yourweek-shell:`, не IndexedDB. Очистка данных сайта может удалить и оболочку, и задачи — кэш не заменяет резервную копию.

## Данные

Задачи хранятся только в IndexedDB этого origin и браузерного профиля. Смена адреса, порта или профиля не переносит их. Используйте один браузерный профиль и одну рабочую вкладку. Приложение не отправляет пользовательские данные, не загружает внешние шрифты и аналитику, не открывает ссылки из задач.

При ошибке записи задача не появляется на доске, сообщение явно указывает несохранённость, а введённый текст остаётся для повторной попытки. Недоступная база не заменяется временным хранением.

### JSON-копия

В разделе «Данные» скачайте полную JSON-копию (формат `yourweek-backup` версии 1) и вручную перенесите её на другое устройство или в другой профиль: выберите «Восстановить JSON», проверьте количество задач и списков, при необходимости скачайте текущую копию и явно подтвердите полную замену. До подтверждения можно отменить без изменений. Настройки, чек-листы, цвета, порядок и история CSV сохраняются; после восстановления открывается текущая неделя, выбранная неделя в копию не входит. Копия содержит личные данные открытым текстом — храните её безопасно. [Формат резервной копии v1](docs/backup-format-v1.md).

### CSV-импорт из Tweek

Выберите локальный файл «Tweek CSV», проверьте preview и подтвердите добавление. Отмена ничего не записывает; импорт не заменяет текущий план и не переключает неделю. Повтор **тех же байтов** файла (в том числе с другим именем) добавляет ноль; изменённый файл считается новым. Одинаковые строки внутри файла сохраняются отдельно. CSV не содержит правил повторения: серии не восстанавливаются, после последней выгруженной даты новые вхождения не создаются, а отсутствующие в файле списки и их задачи не восстанавливаются. [Полный CSV-контракт](docs/csv-import.md).

## Браузеры и лицензия

Целевые браузеры — актуальные Chromium/Chrome, Firefox и Safari. Chromium и настоящий Firefox проверены автоматизированно; native Safari на Linux недоступен и **не проверен**, WebKit не считается Safari. Мобильная раскладка проверена при 360 CSS px в desktop automation, не на физическом телефоне; реальная квота хранилища и скринридеры не проверялись. [Фактическая приёмка и ограничения](docs/acceptance-report.md).

Собственный код — [MIT](LICENSE). [Уведомления и совместимость зависимостей](THIRD_PARTY_NOTICES.md); эти файлы включены в оболочку.

Каждая конфигурация сама собирает production-сервер (`next build` + `next start`) на своём порту, кроме `test:next-dev` и `test:next-csv-storage` (next dev). Запускайте их последовательно: сборки используют общий `.next`. Тесты используют настоящий Chromium/Firefox с настоящими IndexedDB и service worker; все данные синтетические, личные CSV не нужны. Маршрут `/dev-storage` существует только для real-storage проверок в dev-режиме и отдаёт 404 в production.

## Границы модулей

- `app/` — декларативный React-интерфейс: `planner.tsx` (композиция: загрузка/ошибка/повтор, неделя, настройки, фильтр), `day-section.tsx`, `someday-section.tsx`, `task-container.tsx`, `task-editor.tsx`, `search.tsx`, `data-section.tsx`, `csv-import.tsx`, `week-navigation.tsx`, `day-refresh.ts` (обновление доски на смену календарного дня: интервал, `focus`, `visibilitychange`), `drag.ts`.
- `src/model.ts` — задачи, списки и взаимоисключающее размещение по дате или списку.
- `src/storage.ts` — IndexedDB со схемой v3, атомарные операции задач, списков, импорта и восстановления. Успех только после завершения транзакции; обновление схемы сохраняет данные.
- `src/calendar.ts` — локальные календарные даты без UTC и расчёт недели.
- `src/csv.ts`, `src/backup.ts`, `src/placement.ts` — контракты CSV, копии и размещения без DOM.
- `src/editor.ts` — типы действий и маршрутизация редактора; реализация — `app/task-editor.tsx`.
- `src/offline.ts` и `scripts/sw.js` — регистрация офлайн-оболочки и шаблон worker; `scripts/build-next.mjs` собирает оболочку, `scripts/build.mjs` содержит генератор манифеста `generateShell`.

Версии инструментов закреплены по npm registry; TypeScript 6.0.3 выбран вместо latest 7.0.2 из-за ограничения совместимости typescript-eslint `<6.1`.
